# “动作被截断”具体指什么

**使用规则已按用户要求更正：只需每工况一组完整 M 峰。** 下文证实的是后段导出覆盖不足，不能据此排除前面已完整的片段。例如本文同一文件的 5.30–11.08 秒已保留。见 [一组 M 峰复核](EXP_ONE_CYCLE_REVIEW.zh-CN.md)。

这里更准确的说法是：**相对完整 EMG / IK 采集，已有 CEINMS 导出的时间覆盖不完整；有些活动尚未结束，activation、LMT、Torque 等文件就没有后续行了。** 这不等于原始 EMG 本身全部损坏。

## 一个可直接复查的例子

目录：`Data/240725Exp/CalibrationData/dynamics_stoop_5kg_45/`。

把该目录 `emgFilt.sto` 第一条时间戳 `1721913514.18443` 当作共同零点。所有文件只减去这同一个数，没有重新平移动作、改变时间比例或按曲线拟合时间延迟。

| 文件 | 最后一条有效记录的绝对时间戳 | 相对共同零点的结束时间 |
|---|---:|---:|
| `emgFilt.sto` | 1721913575.27443 | **61.090 s** |
| `ik.sto` | 1721913575.15943 | **60.975 s** |
| `emg.sto` | 1721913530.34943 | **16.165 s** |
| `Activations.sto` | 1721913530.34943 | **16.165 s** |
| `lmt.sto` | 1721913530.29743 | **16.113 s** |
| `Torque.sto` | 1721913530.29743 | **16.113 s** |

`Activations.sto` 实际有 596 条数据记录，最后一条是文件物理第 **601 行**，时间戳就是 `1721913530.34943`。所有 activation 数据行列数完整，文件头虽然写 `nRows=0`，这里按实际数据行读取，没有把文件头当作真实行数。

## 截掉的不是只有最后一段等待

![同一次记录的 EMG、activation、IK 和 Torque，含结束位置附近放大](exp_truncation_evidence/240725Exp_5kg45_cut_detail.png)

左列是前 32 秒，右列放大 12–21 秒。四行分别为：

1. 记录的 filtered EMG，取双侧三组背部传感器共六通道均值。
2. CEINMS activation，取原来六个背部代表肌肉的均值。
3. `ik.sto` 的 L5/S1 原始存储值，用来确认记录中仍存在运动；没有 rescale 成 reference，也不是当前 Hill 模型的输出 theta。
4. 原文件 `Torque.sto` 的 CEINMS 力矩。

红虚线为 activation 的 **16.165 s** 终点，红色阴影表示相应文件没有导出数据。没有把后半段补零、延长最后一个值或通过插值补出 activation。

- 完整 EMG 中，约 **13.37–19.15 s** 有一段活动窗口。16.165 s 落在其中，后续 EMG 还有明显变化，IK 也继续变化，因此当前导出没有覆盖这段活动的后半部分。
- 约 **21.14–26.54 s** 又有一段明显活动窗口，EMG 和 IK 都保留了它，但该时段没有对应的 activation、LMT 和 Torque 导出。
- activation 最后一个六通道均值约为 **0.270**，Torque 最后一个有效值约为 **112.1 N·m**。图中曲线在文件终点结束；不能把“没有下一行”解释为 activation 或力矩自然回到了零。

这些窗口来自已有 EMG 活动筛查，只用于定位证据，不据此声称是两次相互独立的完整提举试验。三个不同信号层级在各自坐标轴显示，也没有通过幅值归一化让 EMG 与 activation 看起来相同。

## 另一组也有相同的覆盖差异

![两个原始目录中各文件的原生时间覆盖](exp_truncation_evidence/native_file_endpoints.png)

`240730Exp/CalibrationData/dynamics_stoop_12.5kg_45/` 中，activation 结束于相对 EMG 起点 **17.581 s**，Torque 结束于 **17.471 s**，而完整 EMG / IK 分别到 **51.349 / 51.229 s**。因此问题不是根据不同 subject 的两条曲线作出的推测，而是在每个相同原始目录里逐文件直接核对得到的。

## “需要恢复一致的处理”是什么意思

MAP 训练要知道完整动作中每个相位的肌肉信号；联合 BSE 训练还需要同一时段的 activation、肌腱/肌肉几何和力矩。现有导出只覆盖活动前半段时，截取共同时间区间可能把完整动作变成半个动作，缺失的后续活动也不能直接用于现有流程。

恢复处理指：**利用仍保存的完整 EMG、IK 和相应校准/模型设置，重新导出或重算所需时段的 activation 及关联肌骨数据，然后按真实共同时钟重新验收。** 若只分析已有短导出，则只能从其实际共同覆盖内挑选完整片段；不能把 EMG 波形直接换名当作 activation，也不能把短记录拉长成完整记录。

目前文件能够证明“后段未被这些导出覆盖”，**尚不能单凭文件确定为什么停止导出**：是当时只配置了某段处理、某条处理链提前结束，还是其他记录问题，需要原采集/导出配置或运行日志才能进一步定位。之前用“截断”一词描述的是这个已证实的覆盖现象，不是在断言程序崩溃或原始采集停止。

逐文件的样本数、最后有效时间戳、物理末行、异常行及 SHA-256 见 [证据 JSON](exp_truncation_evidence/evidence.json) 和 [时间覆盖 CSV](exp_truncation_evidence/native_file_endpoints.csv)。`MuscleForces.sto` 末尾另有一条列数不完整的物理行，证据中单独记录；activation 的上述终点来自完整数据行。

在项目根目录运行 `python experiments/multi_subject/show_export_truncation.py` 可重新生成图和原生终点证据，原始文件不被修改。
