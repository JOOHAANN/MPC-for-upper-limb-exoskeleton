## 黄色为什么低于蓝色

**颜色区分处理阶段，两种颜色都来自实验记录，并不是实验输入与 MAP 输出的区别。** 黄色 E 取完整 `emgFilt.sto` 中六个背部传感器通道的均值；蓝色 A 取 `Activations.sto` 中对应六个背部代表肌肉的 activation 均值。两类选段均使用相同的 5 ms 和 300 ms 高斯平滑，没有为画图按峰值归一化，也没有对黄色另加放大倍数。

已有 CEINMS 导出在每个通道上满足指数映射：

\[
a_i=\frac{\exp(A_i u_i)-1}{\exp(A_i)-1}.
\]

这里的 \(u_i\) 是 `emg.sto` 中与 activation 同时刻的模型输入，\(A_i\) 是原 XML 的 `shapeFactor`；不要把图例 A 与公式形状参数 A 混淆。240725Exp 的六通道参数均为 **−2.13108325449385**，与 `240723PilotCalibrated.xml` 一致；240730Exp 均为 **−2.77886425366985**，与 `240725PilotCalibrated.xml` 一致。文件名中的 Pilot 日期不是本轮重新标定的结论，这里只是核对已有记录实际采用的转换。

对两组各 25 个基本文件，在原始 EMG/activation **完全相同的时间戳**上逐通道核对：50/50 均吻合，最大 RMSE 约 **5.04×10⁻¹⁶**。这是原有数值处理关系的验证，不能据此说已有激活参数已经是这两组 subject 的最佳生理标定。

在 730 这组参数下，单通道输入 0.20 转换后约为 0.45，0.40 转换后约为 0.72；中低幅值被非线性抬高，因而 activation 常比其 EMG 输入高。相同平滑也会降低尖峰，但不能解释这里两种颜色之间的主要系统差异。完整 filtered EMG 与模型输入 EMG 还会有采样时刻等小差异，不能宣称两个文件逐样本相同。

![同一试次同一时间段的 EMG 与 activation](exp_one_cycle_review/240730Exp_EMG_activation_levels.png)

这张补充图固定使用 730 的 `10 kg / 45`、4.592–9.802 秒：上图按相同平滑叠加两个处理阶段，左下是读取旧参数得到的映射曲线，右下是原生时间戳上的导出核对。非线性转换先逐通道计算，再取均值；不能先平均 EMG 后套一次公式。数据、转换参数及计算误差可查 [signal_level_verification.json](exp_one_cycle_review/signal_level_verification.json)。

因此黄色较低本身不代表受试者发力较弱或数据质量较差。进入训练前，所有工况应从一致的 EMG 定义出发，采用每位 subject 统一的转换约定；不能将已有 activation 再转换一遍，也不能逐工况调整增益来让图变高。

240528Pilot 与 240617Pilot 也已按相同时间戳逐通道检查：60 份可核对记录都符合 +0.1 的近似恒等映射，没有这种明显抬高，另有 4 份补录过短。对照图及逐文件统计见 [旧 Pilot 的幅值核查](ACTIVATION_LEVEL_AUDIT.zh-CN.md)。

## 仍存在的具体问题

1. **肌骨配套导出覆盖不足仍存在。** 725 的 25 个选中窗口中，3 个被当前整套肌骨导出完整覆盖；730 的 23 个窗口中为 9 个。其余窗口的完整 EMG 不等于已有完整 activation、LMT、肌肉力和 Torque。只选择一组 M 峰减少了所需数据量，但不会补出选中时段里实际没有的模型输出。
2. **730 有 3 个平滑待复核工况：5 kg / 45、7.5 kg / 55、7.5 kg / 65。** 这些片段的高频指标超过原基准上界，图中标星。E 类传感器均值与原合并 activation 层级不同，该对照作为诊断，不作为已证明两者平滑等价的依据。
3. **730 的 7.5 kg / 35 有冲突重复时刻，但不再整份排除。** 本轮不平均冲突值；定位时移除该点，并排除其前后各 0.2 秒滤波影响范围。实际保留窗口为相对完整 EMG起点 **19.51–25.64 秒**，与该排除区间不重叠，窗口内来源最大间隔约 111 ms。这符合“只需要一组有效 M 峰”的局部验收要求。
4. **两个补录可补上工况，另一个补录本身不完整。** `5kg_35_1` 和 `10kg_35_1` 按原项目编号重复的命名方式，分别补上同标签工况；`5kg_45_2` 的 IK 数据缺失、过短或含非有限值，未被纳入。没有用 `_exp` / `_test` 这类无明确速度标签的文件冒充某个基本工况。
5. **部分 IK 与现有 Torque 的相位关系仍需复核。** 例如 725 两个 A 类窗口的零时滞角度/力矩相关性约 −0.074、+0.054。相关性本身不是硬件同步判据，也不能仅据此断言数据错误；需要与动作、负载和后续模型残差一起检查。本轮把数值记录在 CSV，保留原时钟与原坐标，没有为提高相关性自动移位或翻转角度。

因此，**240725Exp 优先进入统一预处理，240730Exp 使用保留的 23 个工况并单列问题**。有候选信号不等于已完成五负载 MAP 泛化验证或联合 BSE 标定；单工况一组动作可以用于拟合，但验证必须保留未参与拟合的工况/记录，不能把同一动作的不同时间点当作独立留出实验。

## IK 的来源和用户更正

两组保存的 `executionRT_XsensEMG.xml` 都配置 `PluginXsensAngleUpperLimb.dll`，各自目录没有配套的光学 C3D、QTM、TRC 或 MOT。用户已确认没有 Qualisys，故直接继续使用现有 `ik.sto`。文件头本身没有记录运行时设备，本轮不把配置证据夸大成逐试次设备审计。

原 reference 的 Scale 约定保持不变；本轮只显示原始 IK 的活动范围，不为每段选中的 M 峰单独 rescale 角度。其他 Pilot 试次的 Qualisys 数据没有被挪用到这两组 Exp。
